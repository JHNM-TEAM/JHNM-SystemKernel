## 🧩 一、系统定义 · Definition

**JHNM-SystemKernel** 是景华时代新媒体部的运行本体，
负责整个新媒体内容体系的命名规则、执行逻辑、任务函数与版本追踪机制。

该仓库不是内容存储库，而是为 E01–E08 各账号提供标准与执行引擎的「系统层」。
它为所有团队成员、AI协作者、内容层仓库（JHNM-ContentLayer）
提供统一的逻辑接口与规则支撑。

## ⚙️ 二、系统结构 · Architecture

| 模块 | 职能 |
|------|------|
| **/01-CORE** | 系统主内核、EID注册、VXTS守护 |
| **/02-OPS** | 日更任务与账号执行逻辑 |
| **/03-CFG** | 命名规范、自动化配置、Codex参数 |
| **/04-NTW** | 内容任务队列与生成计划 |
| **/05-AI-Bridge** | Codex & GPT-API 对接层 |
| **/06-META** | 主权元数据、日志追踪与溯源 |
| **/09-VIS** | 视频与视觉成果导出层 |

---

## 🧱 三、核心机制 · Core Mechanisms

| 机制                | 说明                                                         |
| ----------------- | ---------------------------------------------------------- |
| **通用命名体系**    | 每个文件遵循 `[功能主编号]-JHNM-[模块代号]-[文件名]-［诞生地］-Vx.x-YYYYMMDD.md` 格式，确保可追溯性。 |
| **.jhmeta 元文件机制** | 所有任务与脚本附带元数据头部，记录作者、版本、关键词、状态链锚。                           |
| **VXTS 时间锚系统**    | 自动生成真实时间标识，用于版本同步与AI审校。                                    |
| **非覆盖式版本演化**     | 所有文件改动以新版本文件保存，旧版永久留存。                                     |
| **系统与内容分离**      | Kernel 仅定义逻辑，内容存储与生产由 ContentLayer 仓库负责。                   |

---

## 🧬 四、命名规范 · Naming Logic

### 🧩 系统层文件格式：

`[功能主编号]-JHNM-[功能代号]-[文件名]-［诞生地］-Vx.x-YYYYMMDD.md`

> 示例：`002-JHNM-OPS-AutoDailyTask-JHNM第3场域-V2.2-20251025.md`

### 🪶 内容层文件（对应 ContentLayer）格式：

`E[编号]-T[任务编号]-[Emoji帐号名]-[任务简述]-[作者]-Vx.x-YYYYMMDD.md`

> 示例：`E06-T002-⚙️柳州景硕高考志愿-硬核干货五集主脚本-梁思景-V0.3-20251022.md`
